│   │   └── approval/          │   │   └── approval/

### 2.2 Backend (Spring Boot — Vertical Slice)
```
backend/src/main/java/dau/dx/api/
├── DauDxApiApplication.java
├── common/
│   ├── config/                # 빈 등록, 보안, MyBatis
│   ├── filter/                # ApiKeyAuthFilter, RequestLoggingFilter
│   ├── exception/             # GlobalExceptionHandler
│   ├── audit/                 # AuditableEntity, AuditAware
│   ├── response/              # ApiResponse<T>
│   └── util/                  # IpUtil, MaskUtil, CryptoUtil
├── feature/
│   ├── auth/                  # 로그인, JWT
│   ├── user/                  # 사용자 CRUD/승인
│   ├── api/                   # API 등록·조회·수정·삭제
│   ├── datasource/            # 데이터소스 등록·풀 hot-swap
│   ├── extsystem/             # 연계시스템 등록
│   ├── gateway/               # 외부 호출 동적 라우팅 (★ 핵심)
│   │   ├── controller/        #   GatewayController (catch-all)
│   │   ├── service/           #   ExecutionService, AuthService
│   │   ├── routing/           #   AbstractRoutingDataSource
│   │   ├── execution/         #   DynamicSqlExecutor (MyBatis)
│   │   └── masking/           #   MaskingService
│   ├── monitoring/            # 호출 이력 수집·검색
│   ├── docs/                  # OpenAPI 자동 생성
│   └── approval/              # 사용 승인 워크플로우
└── ...
```

> Vertical Slice 패턴: 기능 단위로 controller/service/repository/dto 를 한 폴더에 묶어 응집도 ↑.

### 2.3 데이터 계층
- **MetaDB (Oracle 19c)**: 본 시스템의 운영 데이터 (사용자/API/데이터소스/연계시스템/이력)
- **업무 DB (N개)**: 사용자가 등록한 외부 DB. 동적 등록·라우팅, hot-swap 지원
- **Redis**: 캐시(인증키, API 메타, OpenAPI 스펙) + 큐(호출 이력)

## 4. 데이터 흐름 (Data Flow)

### 4.1 외부 호출 게이트웨이 (가장 중요)

```
[외부 시스템]
     │ GET /api/sample-user-info?id=1
     │ Header: certification-key=ABC123
     │ Source IP: 10.0.0.5
     ▼
┌─────────────────────────────────────────────┐
│ ① Ingress (TLS 종료, Rate Limit)             │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│ ② Spring Boot Filter Chain                   │
│    ApiKeyAuthFilter                          │
│       a. cert-key → Redis 캐시 조회 (또는 MetaDB) │
│       b. IP ∈ 허용 IP 검증                    │
│       c. 현재시각 ∈ 사용기간 검증              │
│       d. 요청경로 ∈ 매핑 API 검증              │
│       └─ 실패 시 4xx + audit log              │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│ ③ GatewayController                         │
│    a. 요청경로 → API 메타 조회 (Redis 캐시)    │
│    b. 데이터소스 ID 추출                      │
│    c. RoutingDataSource ThreadLocal 설정     │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│ ④ DynamicSqlExecutor                        │
│    a. MyBatis SqlSession 획득                │
│    b. 등록 SQL + 파라미터 바인딩 (Prepared)   │
│    c. 쿼리 타임아웃 적용                      │
│    d. 결과 Map<String, Object> 반환          │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│ ⑤ MaskingService                             │
│    응답 컬럼별 마스킹 룰 적용                  │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│ ⑥ Content Negotiation                        │
│    Accept: json → Jackson, xml → Jackson XML │
└─────────────────┬───────────────────────────┘
                  ▼
              [외부 시스템]
                  │
                  └─ 비동기: CallHistoryProducer.send(...)
                                │
                                ▼
                        Redis Stream / BlockingQueue
                                │
                                ▼
                        CallHistoryConsumer (100건/1초)
                                │
                                ▼
                        MetaDB INSERT (배치)
```

### 4.2 데이터소스 동적 등록·교체

```
[관리자] datasource 등록 화면 → POST /admin/datasource
              │
              ▼
       DataSourceController.save()
              │
              ▼
       DataSourceService.saveAndReload()
       1. MetaDB INSERT/UPDATE
       2. DataSourceManager.register(dsId, props)
          a. HikariCP 신규 풀 생성
          b. Map<dsId, HikariDataSource> 갱신
          c. RoutingDataSource.afterPropertiesSet() 재호출
          d. 기존 풀(존재 시) graceful drain
              - 신규 요청 차단
              - in-flight 쿼리 완료까지 대기
              - close()
```

### 4.3 관리자 콘솔 (CRUD)

```
[브라우저] → Next.js (SSR or CSR)
         │ TanStack Query
         ▼
       Server Action (api/proxy/*)
         │ X-API-Key 주입 (서버 환경 변수)
         ▼
       Spring Boot /admin/**
         │ JWT 검증 + 권한 체크
         ▼
       Service Layer (비즈니스 로직)
         │
         ▼
       MyBatis Mapper → MetaDB
```

### 5.1 프론트엔드 패키지 매니저 정책 (Bun/npm 분리)

본 프로젝트는 **로컬 개발은 Bun, CI/CD 빌드·배포는 npm** 으로 명확히 분리한다. 두 도구는 동일한 `package.json` 을 공유하므로 의존성 자체는 일치하지만, 락파일·실행환경은 별도로 관리한다.

| 구분 | 도구 | 사용 시점 | 비고 |
|---|---|---|---|
| **개발 (로컬)** | `bun` | `bun install`, `bun run dev`, `bun run lint`, `bun run test:e2e`, `bunx create-next-app`, `bunx shadcn@latest ...` | 빠른 install / HMR / 스크립트 실행 |
| **CI / Docker 빌드** | `npm` | `npm ci`, `npm run build` | `package-lock.json` 기반 재현 가능 빌드, Trivy/`npm audit` 호환 |
| **프로덕션 런타임 이미지** | (Node.js 런타임) | `node` 또는 `next start` | 패키지 매니저 미사용 (이미 빌드 산출물만 포함) |

**락파일 정책**:
- `package-lock.json` — **단일 진실 공급원(SoT)**. 항상 커밋. CI `npm ci` 의 입력.
- `bun.lock` — 커밋 가능하나 CI 는 무시. 개발자 로컬에서만 사용.
- 의존성 추가 절차: ① `bun add <pkg>` 또는 `bun add -d <pkg>` 로 로컬에서 추가 → ② **반드시 `npm install` 한 번 실행**해 `package-lock.json` 동기화 → ③ 두 락파일 모두 커밋.
- 의존성 차이가 의심되면 CI 가 `npm ci` 직후 `npm ls` 로 검증.

**근거**:
- **Bun(개발)**: Next.js 16 의 cold start / install 시간을 크게 단축. 작은 단위 스크립트도 빠르게 반복 가능.
- **npm(배포)**: Gitea Actions 러너·Harbor·Trivy·`npm audit`(09 §11.1) 등 사내 표준 툴체인이 npm 락파일을 전제. Bun 은 일부 네이티브 모듈·OS/CPU 타깃에서 회귀 가능성이 남아 있어, 운영 빌드의 결정성·롤백 가능성을 우선.

> 본 정책은 [`07 Mockup 개발 계획`](07_Mockup_개발_계획.md) §10, [`08 본 개발 계획`](08_본_개발_계획.md) §2.1, [`10 CI/CD 가이드`](10_CICD_및_운영_가이드.md) §2.2 에 일관 적용된다.

## 7. 보안 모델 (요약)

```
┌─────────────────────────────────────────────────────┐
│              사용자 인증 (관리자 콘솔)                 │
│  ID/PW → bcrypt 검증 → JWT 발급 (Access 15min)        │
│  Refresh Token (24h) → /auth/refresh                 │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│              외부 호출 인증 (게이트웨이)               │
│  4단 검증:                                          │
│   ① certification-key 헤더                          │
│   ② Source IP ∈ 허용 IP                             │
│   ③ 현재시각 ∈ 사용기간                              │
│   ④ 요청경로 ∈ 매핑 API                              │
│  실패 시 401/403 + audit log                        │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│              SQL 안전성                              │
│  - Prepared Statement 강제 (#PARAM)                  │
│  - 등록 시 EXPLAIN PLAN 검증                          │
│  - 화이트리스트: SELECT/INSERT/UPDATE/DELETE/CALL    │
│  - 쿼리 타임아웃 강제 (10s default)                   │
└─────────────────────────────────────────────────────┘
```
