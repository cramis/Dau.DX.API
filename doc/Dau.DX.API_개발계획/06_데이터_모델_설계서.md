## 1. 데이터 모델 개요

### 1.1 ERD (논리 모델)

```
┌──────────────┐  N:M (USR_EXT_SYSTEM_M)  ┌──────────────┐
│  USR_USER_M   │◀─────────────────────────│ USR_EXT_SYS_M│
│ (사용자)       │                          │ (연계시스템)   │
└──────┬────────┘                          └──────┬────────┘
       │ 1:N (등록)                                  │ N:M (EXT_SYS_API_MAP_M)
       ▼                                             ▼
┌──────────────┐                          ┌──────────────┐
│  API_DEF_M    │ N:1 (사용)               │  API_DEF_M    │
│ (API 정의)    │─────────────────────────▶│              │
└──────┬────────┘                          └──────┬────────┘
       │ N:1 (사용)                                  │
       ▼                                             ▼
┌──────────────┐                          ┌──────────────┐
│DATASOURCE_M   │                          │ API_PARAM_M   │
│(데이터소스)    │                          │ API_RESP_M    │
└──────────────┘                          └──────────────┘

┌──────────────┐
│  CALL_HIST_L  │ (호출 이력, 90일 보관 후 OLAP 이관)
└──────────────┘

┌──────────────┐
│  USER_APPR_L  │ (회원가입/API 사용 승인 이력)
└──────────────┘
```

### 1.2 테이블 일람

| 분류   | 테이블                       | 설명                          |
| ------ | ---------------------------- | ----------------------------- |
| 사용자 | `USR_USER_M`                 | 사용자 마스터                 |
| 사용자 | `USR_EXT_SYS_M`              | 연계시스템 마스터             |
| 사용자 | `USR_EXT_SYS_USER_M`         | 사용자 ↔ 연계시스템 매핑      |
| API    | `API_DEF_M`                  | API 정의 마스터               |
| API    | `API_PARAM_M`                | API 입력 파라미터             |
| API    | `API_RESP_M`                 | API 응답 컬럼                 |
| API    | `EXT_SYS_API_MAP_M`          | 연계시스템 ↔ API 매핑         |
| DB     | `DATASOURCE_M`               | 데이터소스 마스터             |
| 이력   | `CALL_HIST_L`                | 호출 이력                     |
| 승인   | `USER_APPR_L`                | 사용자/API 승인 이력          |
| 코드   | `EZ_CODE_M`                  | 공통 코드 (정상/대기/반려 등) |
| 시퀀스 | `SEQ_API_NO`, `SEQ_HIST` ... | 채번 시퀀스                   |

> 명명 규칙: 마스터 `_M`, 이력 `_L`, 매핑/관계 `_MAP_M`.

## 5. 동적 데이터소스 구조

> 본 시스템의 핵심 — 사용자 등록 외부 DB 의 메타와 풀 관리.

### 5.1 메타 (MetaDB)

- `DATASOURCE_M` 에 모든 데이터소스 정의 저장
- 비밀번호는 Vault Transit 암호화 후 `DB_PASSWORD_ENC` 에 저장
- 변경 시 `MOD_DT` 갱신 → 백엔드가 N초 폴링하거나 변경 이벤트로 풀 재구성

### 5.2 런타임 (백엔드 메모리)

```
DataSourceManager (Spring Bean)
├── ConcurrentHashMap<dsId, HikariDataSource>
├── register(dsId, props)
│     - 새 HikariDataSource 생성
│     - 기존 풀이 있으면 graceful drain 후 close
└── unregister(dsId)
      - 사용 중 API 검사
      - drain 후 close
```

### 5.3 라우팅

```
RoutingDataSource extends AbstractRoutingDataSource
└── determineCurrentLookupKey() → ThreadLocal<dsId> 반환
```

요청 진입 시 `GatewayController` 가 API 메타에서 `dsId` 조회 → ThreadLocal 설정 → 트랜잭션 시작 시 `RoutingDataSource` 가 해당 풀 선택.

## 8. 마이그레이션 전략 (기존 EzAPI → Dau.DX.API)

| 기존 객체              | 신규 매핑                                  | 비고                                              |
| ---------------------- | ------------------------------------------ | ------------------------------------------------- |
| 기존 USER 테이블       | `USR_USER_M`                               | 컬럼 매핑 + 비밀번호 재해시 (1회 강제 변경)       |
| 기존 DATASOURCE 테이블 | `DATASOURCE_M`                             | 비밀번호 재암호화 (Vault Transit)                 |
| 기존 API 정의          | `API_DEF_M` + `API_PARAM_M` + `API_RESP_M` | SQL/파라미터/응답 분리                            |
| 기존 인증키            | `USR_EXT_SYS_M.CERT_KEY_HASH`              | 평문 → 해시 변환 (외부 시스템에 평문 재발급 통보) |
| 호출 이력              | (이전 안 함, 새로 시작)                    | 기존 데이터는 OLAP 보관                           |
