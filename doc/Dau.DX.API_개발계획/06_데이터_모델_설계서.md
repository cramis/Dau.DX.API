## 0. 명명 규칙 (Naming Conventions)

### 0.1 테이블

| 규칙 | 형식 | 예 |
|---|---|---|
| 접두어 | `DXAPI_` | `DXAPI_USR_USER_M` |
| 마스터 | `_M` 접미사 | `DXAPI_API_DEF_M` |
| 이력/로그 | `_L` 접미사 | `DXAPI_CALL_HIST_L` |
| 매핑 | `_MAP_M` | `DXAPI_EXT_SYS_API_MAP_M` |

> 단어사전상 `M = {관리}` 의미. 마스터 성격에 부합한다.

### 0.2 컬럼

- **단어사전 우선**. 매핑되는 표준용어가 있으면 그대로 사용.
- 매핑이 없으면 단어사전의 단어를 **조합** 하여 생성.
- 기술 용어 (`HTTP`, `JSON`, `JDBC`, `URL`, `IP`, `SQL`, `MS`, `POOL`, `TIMEOUT`, `DB`) 는 사전에 없어도 그대로 유지.

### 0.3 인덱스 / 시퀀스

| 종류 | 형식 | 예 |
|---|---|---|
| 일반 인덱스 | `IX_DXAPI_<영역>_<핵심컬럼>` | `IX_DXAPI_USR_EMAIL` |
| 유니크 인덱스 | `UX_DXAPI_<영역>_<핵심컬럼>` | `UX_DXAPI_API_REQ_PATH` |
| 시퀀스 | `SEQ_DXAPI_<용도>` | `SEQ_DXAPI_API_NO` |

## 1. 데이터 모델 개요

### 1.1 ERD (논리 모델)

```
┌──────────────────────┐  N:M (DXAPI_USR_EXT_SYS_USER_M)  ┌────────────────────┐
│  DXAPI_USR_USER_M    │◀──────────────────────────────────│ DXAPI_USR_EXT_SYS_M │
│ (사용자)              │                                   │ (연계시스템)         │
└──────┬───────────────┘                                   └──────┬─────────────┘
       │ 1:N (등록)                                                │ N:M (DXAPI_EXT_SYS_API_MAP_M)
       ▼                                                           ▼
┌──────────────────────┐                                  ┌──────────────────────┐
│  DXAPI_API_DEF_M     │ N:1 (사용)                        │  DXAPI_API_DEF_M     │
│ (API 정의)            │──────────────────────────────────▶│                      │
└──────┬───────────────┘                                  └──────┬───────────────┘
       │ N:1 (사용)                                                │
       ▼                                                           ▼
┌──────────────────────┐                                  ┌──────────────────────┐
│  DXAPI_DATASOURCE_M  │                                  │  DXAPI_API_PARAM_M   │
│ (데이터소스)          │                                  │  DXAPI_API_RESP_M    │
└──────────────────────┘                                  └──────────────────────┘

┌──────────────────────┐
│  DXAPI_CALL_HIST_L   │ (호출 이력, 90일 보관 후 OLAP 이관)
└──────────────────────┘

┌──────────────────────┐
│  DXAPI_USER_APPR_L   │ (회원가입/API 사용 승인 이력)
└──────────────────────┘
```

### 1.2 테이블 일람

| 분류   | 테이블                                 | 설명                          |
| ------ | -------------------------------------- | ----------------------------- |
| 사용자 | `DXAPI_USR_USER_M`                     | 사용자 마스터                 |
| 사용자 | `DXAPI_USR_EXT_SYS_M`                  | 연계시스템 마스터             |
| 사용자 | `DXAPI_USR_EXT_SYS_USER_M`             | 사용자 ↔ 연계시스템 매핑      |
| API    | `DXAPI_API_DEF_M`                      | API 정의 마스터               |
| API    | `DXAPI_API_PARAM_M`                    | API 입력 파라미터             |
| API    | `DXAPI_API_RESP_M`                     | API 응답 컬럼                 |
| API    | `DXAPI_EXT_SYS_API_MAP_M`              | 연계시스템 ↔ API 매핑         |
| DB     | `DXAPI_DATASOURCE_M`                   | 데이터소스 마스터             |
| 이력   | `DXAPI_CALL_HIST_L`                    | 호출 이력                     |
| 승인   | `DXAPI_USER_APPR_L`                    | 사용자/API 승인 이력          |
| 코드   | `DXAPI_EZ_CODE_M`                      | 공통 코드 (정상/대기/반려 등) |
| 시퀀스 | `SEQ_DXAPI_API_NO`, `SEQ_DXAPI_HIST` … | 채번 시퀀스                   |

> 모든 테이블은 `DXAPI_` 접두어를 갖는다. 마스터 `_M`, 이력 `_L`, 매핑 `_MAP_M` 접미어 규칙은 유지.

## 5. 동적 데이터소스 구조

> 본 시스템의 핵심 — 사용자 등록 외부 DB 의 메타와 풀 관리.

### 5.1 메타 (MetaDB)

- `DXAPI_DATASOURCE_M` 에 모든 데이터소스 정의 저장
- 비밀번호는 Vault Transit 암호화 후 `DB_ENC_PW` 에 저장
- 변경 시 `MODDT` 갱신 → 백엔드가 N초 폴링하거나 변경 이벤트로 풀 재구성

### 5.2 런타임 (백엔드 메모리)

```
DataSourceManager (Spring Bean)
├── ConcurrentHashMap<dataSrcId, HikariDataSource>
├── register(dataSrcId, props)
│     - 새 HikariDataSource 생성
│     - 기존 풀이 있으면 graceful drain 후 close
└── unregister(dataSrcId)
      - 사용 중 API 검사
      - drain 후 close
```

### 5.3 라우팅

```
RoutingDataSource extends AbstractRoutingDataSource
└── determineCurrentLookupKey() → ThreadLocal<dataSrcId> 반환
```

요청 진입 시 `GatewayController` 가 API 메타에서 `DATA_SRC_ID` 조회 → ThreadLocal 설정 → 트랜잭션 시작 시 `RoutingDataSource` 가 해당 풀 선택.

### 9.3 결정 사항 (참고)

- **테이블 본문은 변경하지 않았다**. 사용자 요청은 "DXAPI 접두어 추가" 였고 `USR_USER_M → DXAPI_USR_USER_M` 라는 1:1 예시가 명시되었기 때문이다. 따라서 테이블명에는 `EXT_SYS`, `EZ_` 같은 비사전 표현이 남아 있다 — 컬럼 표현(`CONTCT_SYST_ID`)과 시각적으로 어긋나지만, 의도된 절충이다. 향후 표준화가 필요하면 별도 PR 로 처리한다.
- **`HASH`, `JSON`, `MS`, `POOL`, `TIMEOUT`, `JDBC`, `URL`, `IP`, `HTTP`, `DB`, `SQL`, `CLIENT`** 는 단어사전에 정의되어 있지 않으나, 업계 표준 기술 용어이므로 그대로 사용한다.
- **`EZ_CODE_M`** 의 `EZ_` 접두어는 기존 EzAPI 의 잔재. 본 변경 범위에서는 유지 (`DXAPI_EZ_CODE_M`).
