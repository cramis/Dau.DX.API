## 2. 화면별 상세 명세

### 2.1 로그인 (`/login`)

**목적**: 사용자 자격증명 검증 후 JWT 발급

**Wireframe**
```
┌──────────────────────────────────────────────┐
│              [로고] 동아대 EzAPI              │
│                                              │
│        API 사용자 서비스 로그인                 │
│                                              │
│   아이디  [____________________]              │
│   비밀번호 [____________________]              │
│                                              │
│   [로그인]  [비밀번호 찾기]  [회원가입]          │
└──────────────────────────────────────────────┘
```

**필드**
| 필드 | 타입 | 검증 |
|---|---|---|
| 아이디 | text | 영소문자 시작, 5~16자 |
| 비밀번호 | password | 8자 이상 |

**동작**
- `[로그인]` → `POST /admin/auth/login` → JWT 발급 → `/api-list` 이동
- `[비밀번호 찾기]` → 이메일 인증 플로우
- `[회원가입]` → `/signup` 이동
- 5회 실패 시 1분 잠금

---

### 2.2 회원가입 (`/signup`)

**목적**: 신규 사용자 가입 신청 (관리자 승인 후 활성화)

**Wireframe**
```
┌──────────────────────────────────────────────┐
│  API 서비스 회원가입                            │
│                                              │
│  아이디 *      [_______]  [중복확인]            │
│  비밀번호 *    [_______]                       │
│  비밀번호 확인 *[_______]                       │
│  이름 *        [_______]                       │
│  휴대폰번호 *  [_______]                       │
│  이메일 *      [_______]                       │
│  기관명 *      [_______]                       │
│  부서명 *      [_______]                       │
│  전화번호      [_______]                       │
│                                              │
│  □ 개인정보 수집·이용 동의 (필수)                 │
│                                              │
│  [회원가입]  [취소]                            │
└──────────────────────────────────────────────┘
```

**검증 규칙** (Zod)
- 아이디: `/^[a-z][a-z0-9]{4,15}$/`
- 비밀번호: 8자 이상, 특수문자 1개+ (`~!@#$%^&*()=+`)
- 휴대폰: `/^010-\d{4}-\d{4}$/`
- 이메일: 표준 RFC 5322

**동작**
- 중복확인: `GET /admin/users/check-id?id=xxx`
- 회원가입: `POST /admin/users/signup` → 관리자 승인 대기 상태 등록

### 2.3 API 목록 (`/api-list`)

**Wireframe**
```
┌─────────────────────────────────────────────────────────────────┐
│  API 목록                          [검색: ___________] [등록]    │
├─────────────────────────────────────────────────────────────────┤
│ │ API번호    │ API명          │ 그룹  │메서드│상태│요청경로     │ │
│ │ A2026...01 │ 사용자정보조회 │ USER  │ GET  │정상│sample-user │ │
│ │ A2026...02 │ 성적저장       │ GRADE │ POST │정상│grade-save  │ │
│ │  ...                                                         │ │
│                                              [<<] 1 2 3 [>>]    │
└─────────────────────────────────────────────────────────────────┘
```

**컬럼**
| 컬럼 | 정렬 | 검색 |
|---|---|---|
| API번호 | ✓ | ✓ |
| API명 | ✓ | ✓ |
| API그룹구분 | ✓ | ✓ |
| API동작구분 (GET/POST) | ✓ | ✓ |
| API상태구분 | ✓ | ✓ |
| 요청경로 | - | ✓ |
| 데이터소스번호 | ✓ | - |
| 등록일시 | ✓ | - |
| 수정일시 | ✓ | - |
| 인증여부 | ✓ | - |

**동작**
- 행 클릭 → 수정 화면
- `[등록]` → `/api-list/new`
- 가상 스크롤 (대량 데이터 대응)

### 2.4 API 등록/수정 (`/api-list/new`, `/api-list/[id]`)

**Wireframe**
```
┌──────────────────────────────────────────────────────────────────┐
│  API 등록 / 수정                                                   │
├──────────────────────────────────────────────────────────────────┤
│  [기본정보] [SQL 소스] [입력 파라미터] [응답 컬럼] [마스킹]            │
├──────────────────────────────────────────────────────────────────┤
│  API번호      [A20260219001]  (자동채번)                           │
│  API명        [_______________________]                           │
│  API그룹      [USER ▼]                                            │
│  HTTP 메서드  [GET ▼]                                              │
│  요청경로     [sample-user-info     ] [중복확인]                    │
│  상태         [정상 ▼]                                              │
│  데이터소스   [Oracle19c-prod ▼]                                    │
│  인증여부     [☑ 인증 필요]                                         │
│  문서노출    [☑ 표시]                                               │
│                                                                  │
│  [SQL 소스 탭]                                                     │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ SELECT user_id, user_nm, dept_nm                          │  │
│  │   FROM v_user                                            │  │
│  │  WHERE user_id = #{user_id}                              │  │
│  └──────────────────────────────────────────────────────────┘  │
│  [SQL 검증]  [실행 테스트]                                          │
│                                                                  │
│  [저장]  [취소]                                                    │
└──────────────────────────────────────────────────────────────────┘
```

**탭 구성**
1. **기본정보** — 위 wireframe 의 상단부
2. **SQL 소스** — Monaco Editor (Oracle PL/SQL 하이라이트)
3. **입력 파라미터** — 동적 행 추가/삭제 (이름, 타입, 필수, 기본값)
4. **응답 컬럼** — 컬럼명, 타입, 한글명, 마스킹 룰
5. **마스킹** — 컬럼별 마스킹 패턴 (XX*, *@*, etc)

**동작**
- `[중복확인]`: `GET /admin/api/check-path?path=xxx`
- `[SQL 검증]`: `POST /admin/api/validate-sql` → EXPLAIN PLAN 결과
- `[실행 테스트]`: 테스트 파라미터 입력 모달 → 결과 미리보기
- `[저장]`: `POST /admin/api` (등록) 또는 `PUT /admin/api/{id}` (수정)

### 2.5 데이터소스 목록·등록·수정 (`/datasource`)

**목록 컬럼**: 데이터소스번호, 데이터소스명, DB종류, JDBC URL(마스킹), 풀 사이즈, 사용여부, 등록일시

**등록/수정 폼**
| 필드 | 타입 | 비고 |
|---|---|---|
| 데이터소스명 | text | 필수, 100자 |
| DB 종류 | select | Oracle / PG / MySQL |
| JDBC URL | text | 필수, 예: `jdbc:oracle:thin:@host:1521:SID` |
| 사용자 | text | 필수 |
| 비밀번호 | password | 필수, **MetaDB 암호화 저장** |
| 풀 사이즈 (min/max) | number | 기본 5/20 |
| 쿼리 타임아웃 | number | 기본 10초 |
| `[연결 테스트]` | button | `POST /admin/datasource/test-connection` |

**동작**: 저장 시 백엔드가 graceful drain → 새 풀로 hot-swap (재시작 없음).

### 2.8.1 비밀번호 찾기 (`/forgot-password`)

**목적**: 비로그인 사용자가 등록 이메일로 재설정 링크를 받는다 (FR1.4).

```
┌──────────────────────────────────────────────┐
│  비밀번호 찾기                                  │
│                                              │
│  가입 시 등록한 이메일을 입력하세요.              │
│                                              │
│  이메일  [____________________]                │
│                                              │
│  [재설정 메일 발송]   [로그인으로 돌아가기]        │
└──────────────────────────────────────────────┘
```

**동작**
- `POST /admin/auth/forgot-password` (05 §4.1) → 백엔드가 1회용 토큰 + 만료시각 발급, SMTP 메일 발송
- 메일 링크: `/reset-password?token=...` (별도 페이지, 본 절 §2.8.2 로 추후 정의)
- 이메일이 등록되지 않은 경우에도 동일 응답(존재 여부 노출 금지)

### 2.9 API 승인 (`/approvals/api`)

**컬럼**: 신청일시, 신청자(연계시스템), 신청 API, 사유, 상태(대기/승인/반려), `[승인]` `[반려]`

**동작**:
- `[승인]`: 해당 사용자 소속 연계시스템에 API 자동 매핑
- `[반려]`: 사유 입력 모달 → 신청자에게 이메일 통보

---

### 2.10 사용자 승인 (`/approvals/user`)

**컬럼**: 신청일시, 아이디, 이름, 이메일, 기관, 부서, 상태, `[승인]` `[반려]`

**동작**:
- `[승인]`: 사용자 활성화, 로그인 가능
- `[반려]`: 사유 입력, 신청자에게 이메일 통보

---

### 2.11 사용자 관리 (`/users`) — admin 전용

**컬럼**: 아이디, 이름, 이메일, 기관, 부서, 권한(admin/user), 활성여부, 마지막 로그인, `[수정]` `[비활성화]` `[삭제]`

**상세 화면**: 본인 정보 화면과 동일하나 admin 은 권한·활성여부도 변경 가능

---

### 2.12 본인 정보 (`/me`)

**탭 구성**:
1. **기본 정보** — 이름, 휴대폰, 이메일, 기관, 부서 수정
2. **비밀번호 변경** — 현재 비밀번호 + 신규 비밀번호 + 확인
3. **세션** — 로그아웃, 모든 기기 로그아웃
