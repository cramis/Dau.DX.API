## 1. 문서 목적

본 문서는 `Dau.DX.API` 저장소의 **물리적 디렉토리 배치**를 단일 출처로 정의한다.
- 03·07·08·10 문서에 분산된 폴더 구조를 한 곳에 통합
- Phase 별 (0/1/3/5) 어떤 디렉토리가 언제 추가되는지 명시
- `/doc` 하위의 문서·가이드·지침 카테고리 정의

> **원칙**: 본 문서와 다른 문서의 디렉토리 표기가 충돌하면 **본 문서가 우선**한다. 변경 시 본 문서를 먼저 갱신하고, 영향받는 다른 문서를 동기화한다.

---

## 2. Repo 전략 (재확인)

`Dau.DX.API` 는 **App Monorepo + GitOps Manifest Repo** 의 **2-repo** 구성이다.

| Repo | 용도 | 본 문서 적용 |
|---|---|---|
| `dau.dx.api` | 앱 코드(mockup/frontend/backend), Helm chart, CI workflow, **본 PRD 문서** | §3 ~ §9 (본 문서의 주 대상) |
| `dau.dx.api-gitops` | Argo CD 매니페스트, 환경별 overlay, ExternalSecret CR | §10 (요약, 상세는 [10 §4](10_CICD_및_운영_가이드.md#41-ezapi-gitops-repo-구조)) |

> 본 문서가 다루는 디렉토리는 명시 없는 한 모두 **`dau.dx.api`** 저장소 기준이다.

> **선행/상세**: [03 시스템 아키텍처 §2.2](03_시스템_아키텍처_설계서.md#22-backend-spring-boot--vertical-slice), [08 본 개발 계획 §3](08_본_개발_계획.md#3-backend-정식-구현)

```
backend/
├── build.gradle.kts
├── settings.gradle.kts
├── gradle.properties
├── gradlew / gradlew.bat
├── Dockerfile
└── src/
    ├── main/
    │   ├── java/dau/dx/api/
    │   │   ├── DauDxApiApplication.java
    │   │   ├── common/
    │   │   │   ├── config/                  # 빈 등록, 보안, MyBatis
    │   │   │   ├── filter/                  # ApiKeyAuthFilter, RequestLoggingFilter
    │   │   │   ├── exception/               # GlobalExceptionHandler
    │   │   │   ├── audit/                   # AuditableEntity, AuditAware
    │   │   │   ├── response/                # ApiResponse<T>

    │   │   └── feature/                     # Vertical Slice (controller·service·repository·dto 동거)
    │   │       ├── auth/                    # 로그인, JWT
    │   │       ├── user/                    # 사용자 CRUD/승인
    │   │       ├── api/                     # API 등록·조회·수정·삭제
    │   │       ├── datasource/              # 데이터소스 등록·풀 hot-swap
    │   │       ├── extsystem/               # 연계시스템 등록
    │   │       ├── gateway/                 # 외부 호출 동적 라우팅 (★ 핵심)
    │   │       │   ├── controller/          #   GatewayController (catch-all)
    │   │       │   ├── service/             #   ExecutionService, AuthService
    │   │       │   ├── routing/             #   AbstractRoutingDataSource
    │   │       │   ├── execution/           #   DynamicSqlExecutor (MyBatis)
    │   │       │   └── masking/             #   MaskingService
    │   │       ├── monitoring/              # 호출 이력 수집·검색
    │   │       ├── docs/                    # OpenAPI 자동 생성
    │   │       └── approval/                # 사용 승인 워크플로우
    │   └── resources/
    │       ├── application.yml              # 공통
    │       ├── application-dev.yml
    │       ├── application-stg.yml
    │       ├── application-prod.yml
    │       ├── mapper/                      # MyBatis XML
    │       │   ├── UserMapper.xml
    │       │   ├── ApiMapper.xml
    │       │   └── ...
    │       ├── db/migration/                # Flyway (선택, MetaDB DDL/DML)
    │       └── logback-spring.xml
    └── test/
        ├── java/dau/dx/api/                  # JUnit 5 + Mockito (테스트 미러 구조)
        └── resources/
```

### Vertical Slice 원칙
- 기능 단위로 `controller / service / repository / dto / mapper` 를 한 폴더에 묶는다.
- 공통 횡단 관심사(보안·예외·감사·응답 포맷)만 `common/` 으로 분리.
- 테스트는 운영 코드와 1:1 패키지 미러링.

## 12. 표준 컨벤션 요약

> 상세는 `doc/standards/` 의 각 문서 참조. 본 절은 **합의된 큰 줄기** 만 명시.

### 12.1 식별자 명명
| 대상 | 규칙 | 예 |
|---|---|---|
| Java 패키지 | `dau.dx.api.<layer>.<feature>` | `dau.dx.api.feature.gateway.controller` |
| Java 클래스 | PascalCase + 역할 접미사 | `GatewayController`, `DataSourceManager` |
| TypeScript 파일 | kebab-case (컴포넌트는 PascalCase.tsx) | `api-actions.ts`, `DataTable.tsx` |
| MetaDB 테이블 | `DXAPI_` 접두 + UPPER_SNAKE + `_M`/`_L`/`_MAP_M` 접미 (단어사전 기준) | `DXAPI_API_DEF_M`, `DXAPI_DATASOURCE_M`, `DXAPI_CALL_HIST_L` |
| MetaDB 컬럼 | UPPER_SNAKE (단어사전 표준용어 우선) | `STTUS_DVCD`, `CRTFC_KEY_HASH`, `LTLY_LOGIN_DT` |
| 환경변수 | UPPER_SNAKE | `BACKEND_BASE_URL`, `META_DB_URL` |
| Helm value | camelCase | `backend.replicaCount` |
| K8s 리소스 | `dau-dx-api-{role}` | `dau-dx-api-secrets`, `dau-dx-api-prod` |

### 12.2 브랜치 / 커밋 (요약)
- 기본 브랜치: `main` (= prod 후보), 통합 브랜치: `develop` (= dev 환경).
- 작업 브랜치: `feature/<short-id>`, `fix/<short-id>`, `chore/<short-id>`.
- 커밋: 한 논리 변경 = 한 커밋. 한국어 또는 영어 일관 유지.

### 12.3 파일 헤더 (CLAUDE.md §6 준수)
- 신규 소스 파일 첫 줄에 한 줄 한국어 헤더 주석.
- TypeScript: `// API 등록 폼의 SQL 검증 단계 컴포넌트`
- Java: `// 외부 호출 게이트웨이 catch-all 컨트롤러`
- Python (k6 스크립트는 JS 라 해당 없음, 별도 Python 시 적용): `# KIS API 호출을 비동기로 래핑하는 클라이언트`
- SQL (Flyway 마이그레이션 등): `-- 일별 호출 이력 파티션 생성 마이그레이션`
- YAML (Helm template, K8s manifest, GitHub/Gitea workflow): 첫 줄에 `# <파일 역할>` 한 줄
- 설정 파일(`*.config.*`, `package.json`, `tsconfig.json`, `Chart.yaml` 등 도구 표준 포맷) 은 예외.
