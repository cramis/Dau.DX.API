# 04. 요구 기반 수용 테스트 추적

> 요구(계약·FR)를 시나리오로 바꿔 자동 재현. `요구 ↔ 테스트 메서드 ↔ 상태`. "제대로(요구대로) 됐나"를 표로 답한다. 케이스는 코드가 아니라 **스펙**에서 도출(순환 방지).

**실행.** `cd backend; $env:JAVA_HOME=…; .\gradlew.bat test -Dit.devdb=true` (실 dev Oracle 대상, 게이트 `it.devdb`. DB 없으면 skip). 단위 테스트는 항상 실행.

**위치.** `backend/src/test/java/ac/donga/dxapi/acceptance/` — `AcceptanceITBase`(login·데모키·self-clean) + 4 IT. 전부 `@EnabledIfSystemProperty(it.devdb=true)` + `@SpringBootTest @AutoConfigureMockMvc`.

**최종 실행.** 2026-06-02 · **27 수용 케이스 green** (전체 112 tests green).

## 설계 노트

- **공유 dev DB·격리 없음**(Docker 부재). 변형 케이스는 **self-clean**(생성→단언→`finally` 삭제, 유니크 이름 `currentTimeMillis`). 직렬 실행.
- **단언** = `$.code`(ErrorCode enum 명, HTTP 상태 무관 견고) + `status()`. 매핑 = `common/ErrorCode.java`.
- **drift 주의**. seed API 의 매핑 상태는 공유 DB 에서 변할 수 있어(예 E001→A004 가 과거 승인됨) 미매핑 검증은 seed 대신 **임시 API** 생성으로 견고화.
- 진짜 격리(Testcontainers/전용 스키마)는 Docker 확보 후 도입 — 그때 보류 항목(승인·async 마스킹) 자동화 + 변형 e2e(day3~6) 재작성.
