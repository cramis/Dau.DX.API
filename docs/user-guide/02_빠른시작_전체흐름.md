> 이 플랫폼의 핵심 사용 흐름을 한 번에 따라가는 빠른 시작. 데이터소스 등록부터 외부 시스템이 실제로 API를 호출하고 관리자가 모니터링에서 확인하기까지를 7단계로 잇고, 각 단계의 상세 문서로 연결한다.

# 02. 빠른 시작 — 전체 흐름

[← 목차로](README.md) · 이전: [01. 시작하기](01_시작하기.md)

---

## 무엇을 만드나

이 플랫폼의 목표는 **"내부 DB 데이터를, 관리자가 SQL 등록만으로 표준 REST API로 만들고, 외부 시스템에 인증키·IP·기간·매핑으로 통제해 안전하게 노출하는 것"** 이다.

아래 7단계를 따라가면 빈 상태에서 시작해 외부 시스템이 실제로 데이터를 받아가는 데까지 완성된다. 각 단계의 자세한 화면 설명은 링크된 문서에 있다.

```
[1] 로그인 ──> [2] 데이터소스 등록 ──> [3] API 등록(SQL) ──> [4] 연계시스템 등록 + 인증키 발급
                                                                      │
        [7] 모니터링에서 확인 <── [6] 외부 시스템이 호출 <── [5] API 매핑 / 승인
```

---

## 1단계 — 로그인

관리자 계정으로 콘솔에 로그인한다. 자세히는 [01. 시작하기](01_시작하기.md).

## 2단계 — 데이터소스 등록

API가 데이터를 읽어올 **데이터베이스 연결**을 먼저 만든다.

- 좌측 **데이터소스** → **데이터소스 추가**.
- 이름, DB 종류(Oracle/PostgreSQL/MySQL), JDBC URL, DB 사용자/비밀번호, 풀 크기를 입력하고 **연결 테스트**로 확인한 뒤 저장한다.

자세히는 [05. 데이터소스](05_데이터소스.md).

## 3단계 — API 등록 (SQL)

데이터를 어떻게 꺼낼지 **SQL과 API 명세**를 등록한다.

- 좌측 **API 관리** → **신규 등록**.
- 5단계 마법사로 진행한다. 기본정보(경로·메서드·데이터소스·인증 필요 여부) → SQL 작성(`#{파라미터}` 바인딩) → 입력 파라미터/응답 컬럼·마스킹 → SQL 검증 → 등록.
- 등록 직후 상태는 보통 **DRAFT(검토)** 다. 외부 호출이 되려면 **ACTIVE(운영)** 여야 한다.

자세히는 [04. API 관리](04_API관리.md).

## 4단계 — 연계시스템 등록 + 인증키 발급

API를 호출할 **외부 시스템**을 등록하고 **인증키(X-Cert-Key)** 를 발급한다.

- 좌측 **연계시스템** → **연계시스템 추가**.
- 이름, **허용 IP**, **이용 기간**(시작~종료), **매핑 API**(이 시스템이 부를 수 있는 API), 담당자, (선택) 분당 호출 한도를 입력한다.
- 저장하면 인증키가 **딱 한 번** 화면에 표시된다. 반드시 복사해 외부 시스템 담당자에게 전달한다.

> ⚠ 인증키는 발급 시 1회만 보인다. 창을 닫으면 다시 볼 수 없고, 분실 시 **키 재발급**으로 새 키를 만들어야 한다(기존 키는 즉시 무효).

자세히는 [06. 연계시스템](06_연계시스템.md).

## 5단계 — 매핑 / 승인

외부 시스템이 어떤 API를 부를지는 **매핑**으로 정해진다. 매핑은 두 경로로 생긴다.

- 4단계에서 연계시스템을 만들 때 **매핑 API** 를 직접 선택, 또는
- 외부 시스템이 **API 사용 신청**을 올리면 관리자가 [07. 승인 관리](07_승인관리.md)에서 **승인**(승인 시 매핑 추가).

API 상태가 **ACTIVE** 인지도 이때 확인한다.

## 6단계 — 외부 시스템이 호출

외부 시스템은 발급받은 인증키를 헤더에 담아 게이트웨이를 호출한다.

```bash
curl -H 'X-Cert-Key: <발급받은_인증키>' \
  'http://localhost:8080/api/sample/<API경로>?<파라미터>'
```

호출은 서버에서 **라우팅 → 인증키 → 활성 → IP → 기간 → 매핑 → (레이트리밋) → 필수 파라미터 → SQL 실행 → 응답 마스킹** 순으로 처리된다. 응답은 항상 `{ ok, data, traceId }` 형태다.

자세히는 [11. 외부 API 호출 가이드](11_외부_API호출_가이드.md). 외부 개발자는 [10. API 문서 공개 페이지](10_API문서_공개페이지.md)에서 호출 가능한 API와 파라미터를 찾을 수 있다.

## 7단계 — 모니터링에서 확인

모든 호출은 자동으로 이력에 적재된다. 좌측 **실시간 모니터링**에서 분당 호출량·오류율·응답시간과 호출 이력을 확인하고, 개별 호출은 `trace-id` 로 추적한다.

자세히는 [08. 모니터링](08_모니터링.md).

---

## "끝났다"는 어떤 모습

외부 시스템이 `X-Cert-Key` 로 `/api/sample/{경로}` 를 호출 → 4단 검증 통과 → 대상 DB에서 SQL 실행 → 마스킹된 응답 수신 → 호출 이력 적재 → 관리자가 모니터링에서 그 호출을 확인. 이 한 바퀴가 돌면 성공이다.
