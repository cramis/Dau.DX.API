# 05. 데이터소스

## 이 화면은 무엇

API가 SQL을 실행할 **데이터베이스 연결(풀)** 을 관리하는 화면이다(`/datasource`). API를 등록하기 전에 데이터소스가 먼저 있어야 한다.

## 화면 구성

- 상단 지표 — 총 데이터소스, 올해 재시작 사례, 진행 중 hot-swap, 평균 풀 사용률.
- 상단 버튼 — **헬스체크**(상태 새로고침), **JSON 내보내기/가져오기**, **데이터소스 추가**.
- 검색창 — 이름·JDBC URL·ID 검색.

### 표 컬럼

| 컬럼 | 설명 |
|---|---|
| 이름 | 데이터소스 이름 |
| 종류 | Oracle / PostgreSQL / MySQL |
| JDBC URL | 연결 문자열 |
| 풀 사용 | 사용/최대 커넥션(예 `150/200`) |
| 지연 | 응답 지연(ms) |
| 매핑 API | 이 DB를 쓰는 API 수 |
| 상태 | 정상(초록)·주의(주황)·심각(빨강) |

각 행에는 **무중단 변경**, **수정**, **JSON**, **삭제** 버튼이 있다.

## 데이터소스 추가 · 수정

**데이터소스 추가**(또는 **수정**) 버튼을 누르면 입력 창이 열린다.

| 항목 | 설명 |
|---|---|
| 이름 | 표시 이름(예 `DAU-CORE-PROD`) |
| 종류 | Oracle 19c / PostgreSQL 15 / MySQL 8 |
| JDBC URL | 예 `jdbc:oracle:thin:@host:1521/SID` |
| DB 사용자 | 접속 계정 |
| 쿼리 타임아웃(초) | 최소 1 |
| DB 비밀번호 | 등록 시 필수. 수정 시 비우면 기존 비번 유지 |
| 최소 풀 / 최대 풀 | 커넥션 풀 크기 |
| 운영 중(useYn=Y) | 사용 여부 |

저장 전 **연결 테스트** 버튼으로 실제 접속을 확인한다. 성공하면 응답시간(ms)이, 실패하면 원인이 표시된다.

### 삭제 시 주의

매핑된 API가 있는 데이터소스는 삭제할 수 없다. 시도하면 "매핑된 API 가 있어 삭제할 수 없습니다." 가 뜬다. 먼저 해당 API의 데이터소스를 바꾸거나 API를 정리한다.

## 무중단 변경 (hot-swap)

운영을 멈추지 않고 DB 연결 정보(호스트·계정 등)를 새 것으로 교체하는 기능이다. 기존 풀은 진행 중인 쿼리가 끝나도록 잠시 유지(drain)한 뒤 정리되므로, 교체 중 호출도 보호된다.

행의 **무중단 변경** 버튼을 누르면 5단계 마법사로 진행한다(`/datasource/[id]/swap`).

| 단계 | 화면 | 하는 일 |
|---|---|---|
| 1 | 변경 정보 | 새 DB 종류·JDBC URL·사용자·비밀번호·풀·타임아웃 입력. 비번을 비우면 기존 유지 |
| 2 | 연결 테스트 | 새 정보로 실제 접속 확인. **성공해야** 다음으로 진행 |
| 3 | 영향도 검토 | 이 DB를 쓰는 **API 수**와 영향받는 **연계시스템**을 표로 확인 |
| 4 | Hot-swap 실행 | 새 설정으로 교체. 새 호출은 즉시 새 풀로, 기존 풀은 drain 후 정리 |
| 5 | 완료 | 전환 결과(새 JDBC URL·사용자·기존 풀 drain 시간) 표시 |

> 범위 안내. 단일 인스턴스 기준의 graceful 교체다. canary·트래픽 비율 전환·다중 인스턴스 무중단은 인프라 단계(범위 밖)다.

## 상태 배지 의미

| 상태 | 뜻 |
|---|---|
| 정상(초록) | 지연·풀 사용률 양호 |
| 주의(주황) | 풀이 한도에 근접하거나 지연 상승 |
| 심각(빨강) | 풀 포화 임박 |
