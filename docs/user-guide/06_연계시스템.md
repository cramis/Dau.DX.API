# 06. 연계시스템

[← 목차로](README.md)

## 이 화면은 무엇

이 플랫폼의 API를 호출할 **외부 시스템을 등록하고 권한을 통제**하는 화면이다(`/ext-system`). 여기서 발급한 **인증키(X-Cert-Key)** 로 외부 시스템이 게이트웨이를 호출하며, 어느 API를·어느 IP에서·언제까지 부를 수 있는지를 정한다.

## 화면 구성

- 상단 지표 — 총 연계시스템, 총 매핑 API, 만료 임박(30일 내), 인증키 정책(X-Cert-Key).
- 상단 버튼 — **JSON 내보내기/가져오기**, **연계시스템 추가**.
- 검색창 — 이름·ID·담당자 검색.

### 표 컬럼

| 컬럼 | 설명 |
|---|---|
| 이름 | 시스템 이름 + ID |
| 인증키 | 끝 4자리만 표시(`••••{끝4자리}`). 평문은 발급 시 1회만 노출 |
| 이용 기간 | `시작일 ~ 종료일` |
| 매핑 API | 호출 허용된 API 수 |
| 담당자 | 이름·이메일(선택) |
| 상태 | 활성(초록) / 비활성(회색) |

각 행에 **키 재발급**, **수정**, **JSON**, **삭제** 버튼이 있다.

## 연계시스템 추가

**연계시스템 추가** 버튼을 눌러 입력한다.

| 항목 | 설명 |
|---|---|
| 이름 | 시스템 이름(필수) |
| 허용 IP | 호출을 허용할 IP 목록. CIDR(예 `203.0.113.0/24`) 가능 |
| 이용 기간 | 시작일·종료일. 이 기간 밖 호출은 거부 |
| 매핑 API | 이 시스템이 부를 수 있는 API 선택(체크) |
| 담당자 / 이메일 | 연락처(선택) |
| 분당 호출 한도 | 비우면 전역 기본값(분당 600회) 사용 |
| 상태 | ACTIVE / INACTIVE |

저장하면 인증키가 발급되고 **인증키 발급 완료** 창이 뜬다.

## 인증키 발급 — 1회만 노출 ⚠

> ⚠ **중요.** 발급된 인증키 평문은 **이 창에서 단 한 번만** 보인다. 창을 닫으면 다시 볼 수 없다. 서버에는 해시만 저장되기 때문이다.

발급 창에서 할 일이다.

1. **복사** 버튼으로 인증키를 복사한다("인증키를 복사했습니다." 표시).
2. 외부 시스템 담당자에게 안전하게 전달한다.
3. 전달·보관을 마친 뒤 **확인**으로 닫는다.

외부 시스템은 호출할 때 이 키를 **`X-Cert-Key`** 헤더에 그대로 담아야 한다([11. 외부 API 호출 가이드](11_외부_API호출_가이드.md)).

## 키 재발급

키를 분실했거나 노출이 의심되면 행의 **키 재발급**을 누른다. 확인하면 **기존 키는 즉시 무효화**되고 새 키가 다시 1회만 표시된다. 새 키를 외부 시스템에 다시 전달해야 한다.

## 통제 요소 정리

| 요소 | 역할 | 위반 시 |
|---|---|---|
| 인증키(X-Cert-Key) | 신원 확인 | 401 INVALID_CERT_KEY |
| 상태(ACTIVE) | 사용 가능 여부 | 403 EXT_SYSTEM_INACTIVE |
| 허용 IP | 출발지 제한 | 403 IP_NOT_ALLOWED |
| 이용 기간 | 사용 기간 제한 | 403 OUT_OF_PERIOD |
| 매핑 API | 호출 가능 API 제한 | 403 API_NOT_MAPPED |
| 분당 호출 한도 | 과다 호출 차단 | 429 RATE_LIMITED |

> 삭제 주의. 연계시스템을 삭제하면 발급된 인증키도 즉시 무효화된다.
