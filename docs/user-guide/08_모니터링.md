# 08. 모니터링

## 이 화면은 무엇

게이트웨이로 들어온 모든 호출을 실시간으로 보는 화면이다(`/monitoring`). 호출은 자동으로 이력에 적재되며, 지표는 **5초마다 자동 새로고침**된다.

## 실시간 모니터링

### 화면 구성

- 상단 조절 — 기간 선택(최근 10분 / 30분 / 1시간 / 3시간), **일시정지/재개**, **즉시 갱신**, **알림 규칙** 이동.
- 핵심 지표 — **분당 호출량(RPM)**, **p95 응답시간**(1초 초과 시 빨강), **오류율(5xx)**, **활성 연계시스템** 수.

### 차트와 카드

- **호출량 / 응답코드** — 1분 단위로 2xx·4xx·5xx를 색으로 구분한 선 그래프. 호출이 없으면 샘플 호출 안내가 뜬다.
- **진행 중 인시던트** — 선택한 기간 안에서 5xx가 3건 이상이면 빨강 "LIVE" 카드와 **호출 이력 분석** 버튼이, 평소엔 초록 "정상" 이 표시된다.
- **상위 영향 API (라이브)** — 오류율 기준 상위 API. 경로·호출 수·p95·오류율·주요 오류코드와 **상세** 링크.

## 호출 이력 검색

좌측 **실시간 모니터링 > 호출이력**(`/monitoring/logs`)에서 호출 기록을 검색한다.

- 기간 필터(최근 10분 / 1시간 / 24시간 / 사용자 지정)와 **결과 갱신** 버튼.
- **CSV 내보내기** 로 목록을 내려받는다.
- 표의 한 행을 누르면 그 호출의 상세로 이동한다.

## 호출 상세

개별 호출 화면(`/monitoring/logs/[traceId]`)에서 다음을 본다.

- 응답코드·총 처리시간·DB 시간·호출자(연계시스템·IP).
- **분산 트레이스** — 게이트웨이 → 인증 → 라우팅 → 풀 획득 → DB 실행 → 응답 단계별 소요시간.
- 요청·응답 본문.
- **trace-id 복사** 로 식별자를 복사해 다른 로그와 대조한다.

> trace-id 는 호출마다 부여되는 고유 추적 번호다. 외부 응답에도 `traceId` 로 함께 내려가므로, 외부 개발자가 문제를 문의할 때 이 값으로 정확히 그 호출을 찾을 수 있다.
